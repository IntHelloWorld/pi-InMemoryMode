## 已实现的行为

| 设计要求 | 实现 |
| --- | --- |
| 单目录全文 | 明确扩展名、排除规则、UTF-8 校验和容量上限；挂载时列出纳入与排除情况 |
| 固定会话类别 | 首次聊天前创建 InMemory；拒绝普通会话转换、关闭或重复绑定；类别独立于分支和运行状态 |
| 任务内冻结 | 从真实用户条目定位任务起点；请求时只注入一份 `inmemory.workspace`，工具续轮共用相同基线 |
| 工具实时修改 | 复用宿主编辑匹配、BOM 与换行处理，先形成候选内容，再经过工作区串行提交；`read` 返回最新内容 |
| 创建、删除和移动 | `write`、`memory_delete`、`memory_move` 通过相同提交路径更新文件清单 |
| 下一任务正文省略 | 只处理已完成任务中经过本插件确认成功的 `edit`/`write`；保留普通文字、其他调用、失败与中断任务参数 |
| 原始记录 | 请求派生视图不覆盖原始消息；工具调用、结果、文件对象和来源引用继续保留 |
| 稳定检查点 | `turn_end` 保存轮次状态，`agent_settled` 最终确认任务状态；最终标签挂到可见 assistant 汇报 |
| 精确汇报关联 | 从原始会话管理条目重建 `sessionId + anchorId` 索引，能恢复元数据之前的汇报节点 |
| 原生 `/tree` | 展示前只保留可恢复位置，默认跳过摘要询问；用户指令按其父节点恢复；选择时再次校验，拒绝带摘要导航和不完整中间节点 |
| 文件恢复 | 恢复完整文件集合、内容、BOM、换行和普通文件权限；原路线与新路线分别保留 |
| 外部修改 | 只在操作边界校验，不监听、不轮询；缓存已验证文件信息及正文，必要时读取内容；发现差异先中断，再等待 sync 接纳或 recover 撤销外部修改 |
| 重新加载与启动 | 从当前路径恢复；磁盘差异、未完成事务或待处理标记阻止新任务，保留中断记录和待提交草稿，磁盘比较延迟到新任务开始前或实际文件提交前 |
| 会话切换 | 离开时保存并释放所有权；新会话默认普通类别，聊天前可创建为 InMemory；RPC 验证新会话可取得同一目录 |
| 请求阻止 | 使用输入拦截、工具阻断和显式 `ctx.abort()`；官方 Anthropic 适配器测试确认容量失败时不会调用 fetch |
| 缓存观察 | 记录不包含正文的请求角色/块数和宿主缓存用量；Claude 在任务内保留首个有效缓存位置，继续保留宿主当前标记 |
| VS Code 子项目 | 独立 README、开发文档及 VSIX；集成终端启动和挂载、文件标记、外部修改列表、自动多文件差异和可编辑右侧、整目录 Continue/Recover、带来源的选区和草稿 |

文件正文以原始字节存储，清单以固定路径顺序编码；版本对象写入并刷新后，才发布会话引用。恢复日志记录 `prepared → files-applied → state-committed → done` 阶段。中断日志在明确恢复后完成，不将部分写入伪装成成功。

VS Code 联动通过本机带令牌的通信接口复用现有 Pi 命令，状态刷新不扫描托管文件。新增 `/inmem check` 作为主动检查入口；IDE 发起的接纳和撤销会校验用户查看的版本，磁盘再次变化则更新列表并拒绝旧决定。2026-10-18 已在本机 VS Code 1.142.0 的独立扩展宿主中验证选区触发真实 Pi SDK 工具生命周期、未保存选区、自动多文件差异、右侧编辑、Continue 保存并接纳、Recover 取消/确认、真实集成终端挂载及退出。IDE Continue 复用 sync，不新增终端命令或自动重启模型。模型回复为模拟数据；其他操作系统和主题仍需人工验收。详见 [VS Code 开发文档](../vscode/docs/development.md)。

## 具体接口决定

- 执行中的 steering 与 follow-up 都是当前任务的补充。只有下一次从空闲状态开始的真实用户运行创建新任务。
- 重启后不自动续跑旧任务；未结束任务按未完成处理，保留完整参数。sync 和 recover 均结束旧任务并等待新指令，新指令建立新任务和新基线。
- 任意工具中间节点不在第一版恢复范围内。完整任务检查点、初始/同步管理条目，以及能够解析到起点的用户指令可恢复。
- 原生树展示前使用与导航相同的目标判定规则，只保留有 InMemory 快照的任务起点、最终汇报、初始/同步和压缩点；默认显示全部受支持位置。未完成的中间节点、工具调用、工具结果、后台恢复状态及旧版普通位置直接从展示副本移除，原始会话不变；Ctrl+A 等过滤快捷键不能使它们重新出现。
- 当前宿主缺少展示前扩展事件，因此增加可撤销的 Pi 1.3.0 兼容补丁，提供可修改的 `session_tree_open` 事件。补丁只在原生界面构造前发出事件，并使用事件指定的是否询问摘要；插件负责筛选，不覆盖原生 `/tree` 命令、不替换原生选择器，也不修改用户设置。安装宿主补丁后需重启 Pi。
- 离开会话时不比较磁盘，只保存隐藏的 `position` 记录来持久化当前活动路径；Pi 从最后持久化条目恢复位置，因此不能简单删除这次保存。不在会话离开时自动接纳或覆盖文件。旧版无标签 `sync` 若与前驱的目录配置、工作区、基线、任务、投影和启用状态完全相同，在展示副本中隐藏，原始记录不变；旧版实际同步和具名恢复点保留。
- `/resume` 的 `session_list` 展示事件为当前目录和全部目录的 InMemory 会话添加固定 `[InMemory]` 前缀，普通会话无前缀。不改会话名称、搜索内容或持久化文件。类别依据整个会话是否有 InMemory 检查点判定，旧版关闭点、其他分支及恢复状态均不使类别变化；其他会话只读解析文件并按大小和修改时间缓存，最多并发读取 4 个文件。取消加载不影响会话，不阻止其余有效条目显示。
- `/inmem on` 仅限尚未聊天的新会话。普通会话开始聊天后拒绝转换，InMemory 会话拒绝重复挂载或换目录；`/inmem off` 只返回明确错误，不写检查点、不释放目录占用、不触发模型。需要普通会话时用 `/new` 或 `/resume`。
- InMemory 类别在工作区初始化和模型输入前确定；快照缺失或初始化失败时仍阻止普通请求和写入，不回退到普通工具。运行状态只含 ready、switching 和 needs-recovery；普通会话无托管工作区。
- 旧版混合会话当前落点没有启用检查点时，使用历史挂载配置进入待恢复状态；不读取旧快照冒充当前内容，不覆盖磁盘。用户明确执行 sync 或 recover 后才发布新的启用检查点并允许模型请求。旧版关闭检查点字段仅用于读取兼容，新检查点始终 enabled=true。
- 树中的旧版关闭点、普通用户消息/回复及首次挂载前的路线均隐藏并拒绝导航。请求视图移除旧版 `inmemory.mode` 说明，保留原始记录与普通聊天正文；每次任务仍注入冻结快照，不构造普通模式消息队列。待恢复会话可以离开，使用隐藏位置记录持久化待恢复状态，重新进入后仍需明确恢复。
- 检查点索引直接从原始会话重建，不额外维护可能过期的 `index.json`。省略元数据同时保存在检查点和去重的 `projections/` 中。
- 模型可见的正文参数统一使用 `[historical content omitted]`，成功结果使用“Succeeded.”；标记语义在工作区快照说明头中集中解释一次。完整条目、调用、文件版本和承接基线引用保存在省略元数据中，使用原有调用 ID 关联；不在正文标记里重复发送长引用，也不改原始历史。
- 任务中压缩被取消，防止冻结基线后面的修改记录被摘要移除。空闲压缩成功后更新检查点，下一用户任务建立新基线。
- 所有工作区操作先获取工作区串行锁，再调用宿主文件队列；标准工具仅写候选内容，不在持有宿主文件队列时等待另一层工作区锁。
- 自动比较只在三类位置执行：context_with_system 的新任务首次模型请求前、Workspace.commit 的整批文件提交前、agent_settled 的最终任务收尾。同一任务的续答和补充指令只检查已知运行状态，不重复比较磁盘。实际树恢复在准备写盘时同样执行提交前比较。输入、只读工具、tool_result、turn_end、离开/进入会话、status 和压缩不重复扫描。
- begin 推迟到首次请求检查通过后，冻结工作快照，定位原始用户锚点并保存 task-start。准备阶段检查失败时，旧任务状态不变，不创建新的未完成任务。首次指令及附件先保存为 inmemory.drafts 元数据；sync/recover 通过公开命令导航接口只回退未执行提交的对话位置，不恢复旧文件，然后按明确选择处理磁盘并回填输入框。
- drafts.ts 保存输入原文和图片，恢复时通过 setEditorText 回填文字；再次提交经 input transform 附回图片。steering 和 follow-up 在完整工具边界以自定义用户补充消息依次交付；只有工作区已知状态与容量检查通过才标记已交付，不因此额外扫描磁盘。中断时未交付的补充继续保留，下一任务不执行旧的排队消息。所有原始条目保留，派生请求过滤尚未交付的补充消息。
- 托管工具先基于工作内存形成候选内容，统一在真正写盘前比较一次；一个创建/编辑/移动操作不会重复比较。写入成功后只核对本次目标文件的字节、权限或删除状态，不额外扫描全目录。文件变更与检查共用工作区队列。
- FileIndex 仅缓存当前工作区实例中已经校验的磁盘文件。每次检查仍遍历目录，逐文件比较设备、inode、大小、权限、uid/gid、mtimeNs 和 ctimeNs，稳定且未变的条目复用正文和 FileVersion，不重读或重新哈希。仅时间变化但字节相同则更新文件信息，快照 ID 不变。候选版本通过相同 Buffer 引用复用未修改文件的哈希；不可变存储加载仍独立校验内容，不信任磁盘缓存。
- 参考 Git 的 racy-git 处理，对 mtime/ctime 与内容校验同秒或更晚的条目保守重读，直至后续秒重新读取确认稳定；缓存命中不推进原校验时间。采用 bigint 纳秒字段，读取时核对打开前、读取前后和路径当前的文件信息，拒绝读取期间的变动；打开文件不跟随末级符号链接。一次目录检查全部成功后才发布新的缓存集合；被删除或排除的条目随之移除。
- 实际写入前使所有变更目标的缓存失效，写后强制读取校验，只为验证成功的目标更新缓存。失败操作、恢复和树切换不会沿用变更前的文件信息。缓存独立于 working/baseline，读取到外部版本不代表接纳；重新加载会话创建空缓存，下次既定边界再建立，不改变检查次数、待处理决定、任务内冻结或既有快照格式。
- `/inmem sync` 明确接纳执行时磁盘版本，保存对象、追加 inmemory.external-change 消息，再发布 external 检查点并完成日志。消息显示增改删路径，元数据关联前后版本，消息在完整工具配对之后，不触发模型。没有修改时不产生重复消息。
- `/inmem recover` 备份外部版本并恢复最新有效 workingId，保留任务内所有已成功修改及当前对话路线；旧任务保留未完成检查点，恢复后的状态以隐藏 position 记录保存，不再生成具名 recovery 恢复点。旧 recovery 条目继续用于原路径恢复和 resume，但不作为树中可选节点，后代节点连接到最近的有效祖先。撤销助手修改由用户通过 /tree 完成。两个命令都不续跑旧任务，不接受旧参数；save-change 和 continue 只提示当前入口。
- 任务中发现差异立即 abort，完整工具结果持久化后在 agent_settled 保存 interrupted 检查点和“任务未完成”标签；保存 workingId、原冻结 baselineId、任务锚点、完整省略状态和 pendingExternal。待处理标记和草稿随会话恢复，即使磁盘碰巧被改回也不静默解除。
- 检测差异时复用已读取的磁盘版本生成未同步文件清单，标明增改删和权限变化，不额外扫描或输出正文。待处理检查点的可选 externalSnapshotId 保存检测版本引用，reload/resume 仅从不可变版本重建历史清单；status 继续展示已知结果，sync/recover 成功后清除引用。旧检查点无此字段时仍可恢复。
- 初始化只加载不可变快照、所有权及未完成日志，不扫描当前托管磁盘；已有待处理标记或日志只恢复状态栏，不弹出新的不同步警告。后续输入或 status 说明其历史来源，并等待明确处理；不自动清除标记或日志。离开只保存 position。实际树选择前做文件提交检查，列表打开只验证历史对象，不比较磁盘。
- token 预算是保守估算，并非精确分词。挂载文件的资源上限与请求模型的 token 预算分别检查。

## 验证结果

运行：`npm run check`、`npm test`、`npm run smoke`。

当前 69 项功能测试通过，覆盖：

1. 多次编辑时基线冻结、任务内实时读取、新任务替换基线及历史正文省略。
2. 原始会话文件中的完整参数与派生模型输入相互独立。
3. 用户指令落点、报告检查点、另开路线与切回原路线。
4. 创建、移动、删除、文件集合恢复、BOM/CRLF 和权限存储。
5. 外部修改后的停止、请求阻断、明确恢复和重启后的磁盘冲突处理。
6. steering、follow-up、中断、失败编辑、重新加载，以及空闲时宿主压缩后的新任务基线。
7. 带摘要导航取消、缺失对象拒绝、符号链接防护和重叠挂载冲突。
8. 内容去重、对象损坏检测、配额拒绝、串行修改和多文件提交失败后的恢复。
9. 官方 Anthropic 适配器的完整请求序列化、调用/结果配对、稳定缓存位置，以及取消后不发送 HTTP 请求；recover 后的新任务仍保留原未完成任务的工具配对和完整正文，并使用最新有效工作状态建立新基线。
10. 原生树界面不询问摘要、恢复文件；“全部”和“仅标签”视图不能选择工具节点；双分支展示、损坏目标隐藏，以及普通会话的原生设置保持有效。
11. 选择历史分支后离开并重新载入，保留正确路线且不增加可见分叉；兼容隐藏旧版重复同步记录；离开不能静默接纳修改；明确接纳的外部版本可恢复，无改动的接纳为无副作用操作。
12. 新会话创建专用类别、拒绝关闭/换目录/普通会话转换且无副作用；旧版普通位置阻断请求、明确从磁盘恢复、移除过时指令但保留原始记录；树隐藏并拒绝普通节点，合法检查点仍可双向恢复；缺失旧快照及首次挂载前路线不回退为普通类别。
13. 会话列表固定类别、旧版关闭和其他分支不改变标记、只读缓存更新、原生命名筛选和真实选择路径，以及当前/全部目录范围、不完整尾行、文件消失和取消加载。
14. 空闲无后台比较，status/重载/会话离开无额外扫描；含 steering、follow-up 的四次模型请求加一次写入，整个任务恰好比较三次，新只读任务只增加启动和收尾两次检查。首次请求拦截、写入前防覆盖、只读续答不比较但收尾拦截、原子保存和权限变化均有功能覆盖。
15. 首次任务检查失败时保留长指令、回填输入框并附回图片，前一个完成任务状态不变；sync/recover 均不自动请求模型，recover 保留最新成功修改、tree 可撤销助手修改，排队补充保留且不自动重放，启动前和执行中两种中断均可重开会话后处理。
16. 离开后改文件、历史待处理标记和未完成日志三种恢复场景均不扫描磁盘或弹出新的不同步警告；下一条指令被正确拦截，recover 完成后恢复输入、结束日志并允许新任务。
17. recover 不增加可见恢复点，隐藏状态仍能完成日志并在重开会话后保持可用；旧版具名恢复节点只从视图隐藏，原始记录不变，其后的外部修改仍连接正确祖先且可双向恢复。
18. 实际修改、添加、删除及 chmod 后的提示准确列出对应文件，区分仅权限变化和内容/权限同时变化；特殊文件名不会插入额外行，未变化文件和正文不出现在清单中。status/reload 复用历史检测结果，额外磁盘扫描为零，recover 后清单和引用清除。
19. 文件缓存专项验证：稳定未改文件读取正文为零，只改一个文件只读该文件；touch 不创建内容版本；热缓存下的新增、删除、移动、权限、同大小改写并恢复 mtime、原子替换、同秒时间保护、UTF-8 和容量限制、符号链接替换以及读取期间的替换均有覆盖。缓存可记住尚未接纳的磁盘版本，但不会更新 working；助手写入、sync 和 recover 后仍能正确比较并恢复。测试时钟仅注入 FileIndex，不改进程或共享目录锁的时间。

在隔离临时目录另做真实文件读取验证，使用实际系统时钟、100 个各 8192 字节的文件：首次检查读取 100 个正文，共 819200 字节；经过后续秒的重读确认稳定后，无修改检查读取 0 个正文、复用 100 个；同大小修改 1 个文件后，只读取该文件的 8192 字节、复用其余 99 个。未修改时快照 ID 保持一致，修改后产生不同 ID。此结果统计托管正文读取量；目录和文件信息查询、不可变存储校验仍按各自流程执行。

CLI/RPC 冒烟验证包发现、命令注册、固定类别、拒绝关闭、空闲改动无后台通知且 status 不比较、明确接纳前没有外部消息、接纳后的原生消息队列、空闲检查点撤销，以及新会话普通类别与所有权转移。项目依赖和本机全局 CLI 均通过，不调用模型服务；所有测试使用隔离临时目录，不访问个人模型账号。

## 尚未完成的外部验证与限制

- 尚未使用真实模型服务测量任务内与任务间的缓存命中率。测试中的缓存读取量由模拟服务给出，只证明字段传递和观察功能正常。
- Claude 的适配限定于已验证的 1.3.0 负载结构；其他 API 不主动改写缓存字段，尚未逐一进行提供方协议验证。
- 界面兼容补丁只验证 Pi 1.3.0；宿主升级或重装后需要重新检查安装，其他版本会拒绝自动修改。原文件保留备份，支持从旧版树补丁升级及完整撤销，命令见 README。启动前的 `pi --resume` 选择器未加入标记。
