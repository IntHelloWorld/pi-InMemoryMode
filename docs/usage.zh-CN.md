# InMemoryMode 使用说明

[English overview](../README.md) · [中文概览](../README.zh-CN.md)

第一版（0.1.0）Pi 文档编辑插件，适配 `@earendil-works/pi-coding-agent 1.3.0`。挂载一个文本目录后，任务开始时的文件全文会放在用户指令之前；任务中使用工具持续修改文件，全文基线保持不变。下一条空闲时提交的指令开始后，插件更新基线，并在模型输入里省略已完成任务的重复编辑正文。

原始工具参数和聊天始终保留。使用 Pi 原生 `/tree` 可以同时恢复文件版本和聊天分支。有 In Memory 历史的会话默认不生成分支摘要，树中只显示支持恢复的位置。

省略后的 `write` 参数只保留短标记，例如 `{"path":"docs/晨光.txt","content":"[历史正文已省略]"}`；`edit` 的旧文本和新文本使用同一标记，配对结果简写为“已成功。”。原始条目、文件版本和基线的完整引用保存在检查点与投影元数据中，不在每个正文参数里重复。调用 ID 保留在工具协议字段中，用于配对调用和结果。

## 设计文档

[设计基线](design.md) 保留原始设计与验收要求。[第一版实现与验证记录](implementation.md) 说明本版的具体行为、验证结果和边界。

## 从源码启动

```bash
git clone https://github.com/IntHelloWorld/pi-InMemoryMode.git
cd pi-InMemoryMode
npm ci --ignore-scripts
npm run dev
```

在尚未开始聊天的新会话中，可以绑定仓库提供的小型示例，创建 InMemory 专用会话：

```text
/memory on examples/documents
```

随后输入“为这份提纲补充三个小节”，模型会通过文件工具修改示例。在 `/tree` 里选择带 `Memory：任务完成` 标签的汇报，按回车直接恢复当时的文件，**无需再选 No summary**。选择一条用户指令会回到执行该指令之前。

树中只保留有 InMemory 文件快照的任务起点、最终汇报、初始挂载、外部修改、恢复及历史压缩点；旧版同步点继续兼容。工具调用、工具结果和普通管理条目不出现在可选列表中。即使按 Ctrl+A 切到“全部”，也不会重新出现。完整原始记录仍保存在会话文件里。

切换到其他会话时，插件只保存当前分支位置，不比较或同步磁盘，也不增加可见恢复点。旧版切换会话生成的无标签重复检查点会自动隐藏，原始记录继续保留。

`/resume` 列表在会话标题前显示类别标记，原有名称和历史不变：

| 标记 | 会话类别 |
| --- | --- |
| 无标记 | 从未使用 InMemory 的普通会话 |
| `[InMemory]` | InMemory 专用会话，包括待恢复的会话和旧版混合会话 |

类别属于整个会话，不随树落点、重新加载或恢复状态改变，不再显示“已关闭”标记。当前目录和全部目录两个列表都支持标记；需要加载本插件和下面的界面兼容接口。这里指聊天中的 `/resume`，启动前的 `pi --resume` 选择器不经过插件事件。

## 创建专用会话

会话开始聊天后，类别固定，不支持普通模式与 InMemory 之间转换。创建入口保留 `/memory on [目录]`：先 `/new`，再在第一条聊天前执行该命令；省略目录时使用 Pi 当前工作目录。已经开始聊天的普通会话不能转换。已创建的 InMemory 会话不能通过 `/memory off` 转回普通类别，也不能再次绑定其他目录；需要其他目录时另建会话。

需要普通聊天时，使用 `/new` 创建普通会话，或 `/resume` 选择已有普通会话。离开 InMemory 会话会保存当前位置、释放目录占用，原会话仍保持 InMemory 类别。重新进入后加载检查点和草稿，磁盘比较延迟到新任务开始前或实际文件提交前；发现差异后先选择 sync 或 recover。

旧版允许关闭或混用的会话，统一识别为 InMemory 类别，原始记录不改写。`/tree` 隐藏并拒绝旧版普通位置、关闭点和首次挂载前的位置，只能选择有 InMemory 快照的恢复点。若重新进入时停在旧版普通位置，先进入待恢复状态，阻止模型请求和托管写入；用 `/memory sync` 接纳当前磁盘文件，或用 `/memory recover` 先备份磁盘再恢复旧检查点。不会自动覆盖文件，也不会退回普通模式。

模型输入始终沿所选分支组织：历史聊天、经过规则省略的已完成托管工具记录、当前任务冻结快照、用户指令及本任务新增工具记录。旧版模式切换说明只从请求视图移除，原始历史继续保留；不再构造普通模式的消息队列。

也可以在自己的写作目录运行 `pi -e /absolute/path/to/pi-InMemoryMode`，然后 `/memory on ./manuscript` 挂载作品目录。

修改插件后使用 `/reload` 重新加载。`/plugin-dev` 仍可用于单独确认加载成功。

## 原生界面兼容接口

Pi 1.3.0 原本没有在树显示前筛选节点或为会话列表添加标记的扩展接口，且摘要询问发生在切换事件之前。本项目为该版本补充 `session_tree_open` 和 `session_list` 展示事件，继续使用原生选择器和导航功能，不修改全局设置。会话标记仅参与标题显示，不改名、不影响“仅命名会话”的筛选。没有 In Memory 历史的会话保留 Pi 原有行为。

`npm run dev` 和 `npm test` 会检查并安装项目依赖中的兼容补丁。若使用平时的全局 `pi` 命令，安装插件后执行一次：

```bash
npm run setup:tree -- --global
```

补丁同时覆盖 SDK 和 CLI 使用的代码，验证宿主为 1.3.0 且代码形态匹配后才修改，并保留原文件备份。安装后需要**退出并重启 Pi，再恢复原会话**；`/reload` 只重载插件，不能更新已加载的宿主界面代码。重新安装 Pi 后需要重新执行 setup；其他版本会明确报错，不套用未经验证的补丁。

需要撤销时，在项目目录执行 `npm run setup:tree -- --global --restore`，然后重启 Pi。若要使用插件的新树行为，再执行 setup 即可。

使用全局 Pi 前，请确认版本为 1.3.0。模型账号通过 Pi 内的 `/login` 配置；验证插件加载不需要账号或模型调用。

## 安装与检查

使用 Node.js 24 LTS（版本见 `.nvmrc`），然后执行：

```bash
npm ci --ignore-scripts
npm run check
npm test
npm run smoke
```

测试在临时目录中运行，不需要模型账号。`npm test` 使用真实 Pi SDK、确定性的模拟模型和官方 Anthropic 序列化适配器，验证文件修改、上下文投影、树恢复与异常处理。`smoke` 通过真实 CLI/RPC 验证包加载、命令、固定会话类别、拒绝关闭、切换新会话与写入锁转移；它不调用模型，不写个人 Pi 配置。

## 命令

| 命令 | 用途 |
| --- | --- |
| `/memory on [目录]` | 在尚未聊天的新会话中创建 InMemory；默认绑定 Pi 当前工作目录 |
| `/memory status` | 查看目录、文件数、任务状态、快照和宿主报告的缓存用量 |
| `/memory sync` | 保留当前外部修改，记录专门的外部修改消息和文件版本 |
| `/memory recover` | 撤销外部修改，保留助手已成功的修改，等待新指令；撤销助手修改用 `/tree` |
| `/new` | 新建会话；直接聊天为普通会话，聊天前可创建为 InMemory |
| `/tree` | 使用原生会话树恢复或切换分支 |
| `/resume` | 使用原生会话列表选择普通或 InMemory 会话 |

执行任务期间的 steering 和 follow-up 作为草稿保存，在完整工具边界按顺序交给当前任务，继续共用冻结基线。中断后尚未执行的补充指令保留为草稿，不自动执行。下一条从空闲状态提交的新指令创建新任务；未完成任务的正文参数保持完整。

## 外部修改的处理

自动比较只保留三类检查点，比较磁盘文件与最后有效的工作状态：

1. **新任务开始前**：只在首次模型请求前检查一次，通过后建立任务基线；同一任务的续答和补充指令不重复比较。
2. **托管文件修改提交前**：创建、编辑、删除、移动整批提交前检查一次；实际 `/tree` 恢复也属于文件修改。
3. **整个任务结束前**：通过检查后才标记任务完成。

输入事件只保存指令和附件。只读工具、工具返回、后续模型请求、每轮结束、打开树列表、离开或重新加载会话、空闲压缩都不额外扫描。`/memory status` 只展示最后已知状态，不主动比较。写入后只校验本次操作涉及的文件。没有持续监听或定时轮询；任务中的外部修改要到下一次文件提交前或整个任务结束时才发现。

检查借鉴 Git 的[文件信息缓存](https://git-scm.com/docs/gitformat-index)和[短时间修改防漏检](https://git-scm.com/docs/racy-git)：每次仍遍历托管目录，发现新增、删除和移动；已有文件先比较设备、文件标识、大小、权限、属主以及纳秒级 mtime/ctime。信息相同且时间已确认稳定时，复用已验证的正文和哈希；其他情况读取正文，只有正文或权限实际变化才形成不同的快照。仅 `touch` 不产生新文件版本。

对与内容校验处于同一秒、或时间更新的文件，保守重读，直到后续秒内重新读取确认稳定；不会仅因等待了一段时间就把旧缓存当成可靠结果。读取前后检查文件信息及路径指向，期间发生修改或替换则停止检查。助手写入和树恢复前使涉及文件的缓存失效，写后读取验证成功才更新缓存；候选快照复用未改动文件的哈希。

缓存只保存在当前工作区实例中，不修改已有版本格式。重新加载会话不会扫描磁盘，下一次必要检查重新建立缓存。缓存记录的是磁盘观察结果，外部修改仍与最后有效工作快照比较，必须明确 sync 或 recover 才能继续。

发现变化后备份可读取的磁盘内容，不静默同步。提示列出检测时未同步的文件，区分新增、修改、删除、权限，以及内容和权限同时变化；路径相对托管目录，特殊字符会转义。例如：

```text
未同步文件（3 个，路径相对托管目录）：
  • 修改  "晨光.txt"
  • 新增  "草稿/远山.txt"
  • 删除  "旧稿.txt"
```

随后等待两个命令：

| 操作 | 任务尚未开始 | 任务执行中 |
| --- | --- | --- |
| `/memory sync` | 接纳外部修改、记录修改消息；原指令回填输入框，发送后才执行 | 接纳外部修改、记录修改消息；旧任务结束但保持未完成，等待新指令 |
| `/memory recover` | 撤销外部修改；原指令回填输入框，发送后才执行 | 撤销外部修改，保留助手已成功的修改；旧任务结束但保持未完成，等待新指令 |

例如任务开始时为 A，助手成功改成 B，外部编辑器又改成 C：`sync` 保留 C，`recover` 恢复 B；要回到 A，请通过 `/tree` 选择任务开始前的位置。两个命令均不自动调用模型，下一条用户指令统一建立新任务和新冻结快照。恢复之前保存的外部版本仍可在备份中找到。

`recover` 只保存后台状态，用于记住外部修改已撤销、完成操作日志并支持 `/resume`，不增加独立的“恢复完成”检查点。旧版已生成的“恢复完成”节点也从树中隐藏，原始记录和文件版本保留；其后的“外部修改”等有效节点仍可正常选择。

启动前检查失败时不创建任务，不把上一个完成任务改成未完成。待提交文字、图片附件和排队补充保存在原始会话的草稿元数据中；处理后回填文字，重新发送草稿时附回保留的图片。宿主已记录的未执行指令保留在原分支，处理后当前对话回到这次提交之前，避免重新发送时重复进入上下文。任务中断则保留当前路线和完整工具调用/结果，记录“Memory：任务未完成”。

同步消息列出新增、修改和删除的文件；前后完整版本引用放在消息元数据中，正文不重复长指纹。没有变化时 `sync` 不创建重复消息。重新加载只恢复已知状态和草稿，不自动覆盖磁盘；磁盘比较延迟到下一个检查点。已知待处理状态会继续阻止新任务、写入、树恢复和压缩历史。`save-change`、`continue` 和带参数的旧 `recover --from-*` 均只提示当前两个命令。

`/resume` 或 `/reload` 发现检查点保留了待处理标记、或目录中有未完成操作日志时，只恢复状态栏中的待处理状态，不弹出“本次发现不同步”的警告。提交指令或查看 `/memory status` 时会说明这是上次留下的状态或日志，本次恢复没有比较磁盘。有检测版本记录时也会显示上次的文件清单，不增加磁盘扫描；之后继续发生的外部修改尚未包含在这份历史清单中。仍须明确 sync 或 recover，不自动清除记录。

## 文件规则与容量

默认纳入 UTF-8 的 `.md`、`.txt`、`.json`、`.yaml`、`.yml`、`.toml` 普通文件。排除符号链接、隐藏路径、账户配置，以及 `.git`、`.pi`、`node_modules` 等管理和构建目录。文件原始字节、BOM、换行和普通权限会保存在版本中。

默认上限：100 个文件、单文件 256 KiB、总正文 1 MiB。请求中的快照另受 `min(32768, 模型上下文窗口的 25%)` 约束；总请求预留输出空间和余量。token 数按 UTF-8 字节保守估算，可能明显高于实际值。超出预算会停止，全文不会被截断。

可在 **Pi 工作目录**的 `.pi/inmemory.json` 中配置，在新会话创建 InMemory 时生效：

```json
{
  "extensions": [".md", ".txt", ".json", ".yaml", ".yml", ".toml"],
  "exclude": ["archive", "drafts/old.md"],
  "includeHidden": false,
  "maxFiles": 100,
  "maxFileBytes": 262144,
  "maxTotalBytes": 1048576,
  "maxSnapshotTokens": 32768
}
```

`extensions` 替换默认扩展名列表，`exclude` 使用相对挂载目录的路径前缀，不是通配符。管理目录和账户配置始终排除。首次挂载会显示纳入文件及排除原因。

## 版本保存与本版边界

版本数据位于 Pi 工作目录的 `.pi/inmemory/<目录指纹>/`。正文按 SHA-256 去重，文件清单和检查点不可变；文件操作与树恢复使用恢复日志。插件不自动清理历史。多文件恢复依靠日志和补偿处理，并非整个目录的原子替换。

同一目录及其重叠目录只允许一个插件写入会话。后台编辑器、shell 和其他程序仍能修改磁盘；插件通过操作边界的内容指纹校验检测，不提供操作系统级隔离。两个检查节点之间的修改不会立即中断模型或正在运行的工具。

本版只支持同一挂载根目录内的稳定检查点、初始/同步点和用户指令起点。未完成的工具中间节点会拒绝切换；InMemory 会话取消 `/fork` 和任务中压缩历史，空闲时可正常压缩。若外部文件变成无效 UTF-8、超过容量或变成不安全路径，会停止操作，需要先修正文件，或在新会话中使用调整后的配置。

Claude 的缓存位置保留已通过官方适配器的本地模拟请求验证；状态页会显示宿主报告的缓存用量。**尚未测量真实服务的缓存命中率或费用收益。**其他提供方保留宿主自身的缓存行为。

## 项目结构

- `extension.ts`：扩展入口，导出接收 `ExtensionAPI` 的函数。
- `src/controller.ts`：任务边界、会话检查点、树导航和恢复协调。
- `src/external-changes.ts`：外部文件变化列表、处理提示和消息类型。
- `src/drafts.ts`：待提交指令、附件和补充指令的持久化、交付及输入框回填。
- `src/workspace.ts`、`files.ts`、`store.ts`、`ownership.ts`：工作内存、文件规则、不可变版本、事务日志和共享写入锁。
- `src/tools.ts`：覆盖并复用 Pi 的 `read`、`edit`、`write`，提供 `memory_delete` 和 `memory_move`。
- `src/projection.ts`、`anthropic-cache.ts`：请求时的冻结快照、正文省略和已验证的 Claude 缓存适配。
- `src/tree-view.ts`、`tree-api.ts`、`session-list.ts`：树的位置展示、固定会话类别标记，以及宿主兼容事件声明。
- `scripts/setup-tree-host.mjs`：安装或撤销 Pi 1.3.0 的原生树和会话列表兼容补丁。
- `tests/`：功能与宿主集成测试。
- `package.json`：`pi.extensions` 声明扩展入口；Pi 是宿主提供的 peer dependency，同时作为开发依赖提供 CLI 和类型。
- `tsconfig.json`：严格类型检查，不生成编译产物；Pi 直接加载 TypeScript。
- `smoke.mjs`：不依赖模型的加载验证。
